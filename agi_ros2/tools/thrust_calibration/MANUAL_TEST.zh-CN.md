# 手动遥控器、Blackbox 与 PX4 测力日志操作说明

本文件供操作者在另行确认台架及动力限制后执行。本次软件开发未执行电机操作，工具不连接串口、不发 MSP、不更改 FC 或 PX4 设置。允许推力、电压、转速、温度、高输出持续时间尚未提供，应由操作者填写，不能从传感器 10 kg 量程推导。

步骤0：建立一次试验的配对记录
----------------------------
每次试验记录run_id、battery_id、被测电机编号、桨/电机/电调、传感器及量程、两块板的固件、有效配置、试验profile、日期与备注。
明确哪一个Blackbox文件及其中的log index对应哪个PX4日志/时间段。不能只按文件修改时间自动配对。
一次PX4日志可以覆盖多个BF解锁日志，但每段映射必须明确。两份日志不是同一台架运行时，不允许合并。

步骤1：准备手动测试配置
----------------------
- 停止原树莓派MSP输出程序；AUX4中位、AUX3低、AUX5低，核实模式。
- 保留遥控器ARM/disarm；不为记录而解锁独立PX4测力板。
- 准备独立台架profile，隔离P/I/D/FF产生的角速度修正。仅处理必要增益及会重新派生增益的设置；不要把全部profile参数清零。
- 保留原profile与真实原值，只生成最小修改/恢复清单；不覆盖未确认空闲的profile，不自动写FC。
- 尽量保持与目标飞行一致的RX范围、油门曲线、rateprofile、输出限制、动态怠速和推力线性化；差异必须进入标定元数据并核验影响。
- 第一版ROS承担电压补偿：实际核实FC vbat_sag_compensation关闭；不能因diff没写就视为关闭。
- 当前动态怠速可能使0%命令仍有正推力，并受抬高油门的历史影响，不为获得0N而自动去掉或抵消它。

优先的油门记录方案（不改固件代码）：
- 在实际固件支持且经短日志验证后，临时选用现有debug_mode=RX_SIGNAL_LOSS，并启用Blackbox DEBUG字段。
- 保存原debug_mode=MAVLINK_TELEMETRY，结束后按备份恢复。
- 预检debug[3]是否实际记录rcData[THROTTLE]，核对rxrange及其到原始MSP RC的变换。
- 若该模式/字段不受支持，不随便换一个debug字段解释。可改用已有原始RC字段，或严格验证后从处理后油门反解；证据不足则只能生成中间分析，不能部署。
- 不要求新写固件功能；若现有日志确实无法提供可逆油门轴，准确报告缺口，不能为了完成表格伪造raw RC。

步骤2：确保两边真的在记录，先做短预检
------------------------------------
先在电机不转时，用已知静态载荷及释放检查测力单位、比例、方向和日志记录；通过后再做约20–30秒的低至中等输出短试，保存并实际解码，不要直接开始整套满范围扫描。
PX4要包含真实力topic，而不是仅有驱动状态。独立PX4未解锁时默认logger可能不记录；根据实际固件logger help确认手动记录方式。官方logger status/on/off可用于检查与手动启停，logger on要求模块已运行；这些不是ARM命令。
自定义力topic需确实被logger配置记录。确认实例、字段、独立样本率、单位、方向和零点。ULog自描述字段类型，不保证自定义物理单位能从字段名推断。
Blackbox确认有时间、已核验的油门轴、电压和被测motor输出，强烈建议保留四路motor、rcCommand、setpoint、PID分项、相关状态及可用eRPM。
先用已知静态载荷/释放核验测力比例与符号，再用短电机阶跃检查两份日志均能识别同一变化。
预检不合格先解决记录问题；不要继续收集大量无法利用的日志。

步骤3：记录零点与首组同步标记
----------------------------
PX4先记录稳定无推力基准，例如5–10秒。支架、电机自重的去皮必须在真实无推力状态完成。
BF正常开始Blackbox记录后，在已经确认适合台架的L/H两个输出水平做非等时长阶跃，例如：
  L约3秒，H约2秒，L约5秒，H约3秒，L约4秒，H约2秒，L约3秒。
L/H不预设一个“通用安全百分比”；应有明显力差且在已确认范围内。不要用高速抖动，不要求人工精确计时，分析按真实日志边缘识别。
正式扫描结束仍在记录时重复一组有辨识度的标记；长试验可在中间块间补一组。
这些是BF命令/输出与PX4力响应共同可见的事件；只拍一下力传感器、只在一个日志写标记不构成共同同步证据。

步骤4：完整初扫及回扫
--------------------
以12–20个RC命令目标点作初扫，可用示意点：
  0、5、10、15、20、25、30、40、50、60、70、80、90、100%。
这是操作目标，不作为真实数值标签；分析必须使用日志实际油门。
悬停及纠偏附近可根据初扫结果增加点。
每台阶3–5秒作为起点，排除过渡后使用稳定段。高输出持续时间、无桨电机转速及散热受实际动力约束，不为了凑5秒延长高输出。无可靠稳定窗口的点不计入有效标定。
做升扫、降扫及分块换序，每几个点回到一个参考点，以观察温升、迟滞、漂移。参考点本身推力仍会随电压变化，不把它当恒定力标准。
记录解锁轮次、是否刚解锁、是否已经抬高油门、扫描方向；未能直接读到throttleRaised时标unknown或明确推定来源。

步骤5：重复电压覆盖与留出
------------------------
在高、中、低三个自然带载电压阶段重复同一批输出附近。无需精确维持某个电压，不要求一块电池连续做完，可分多次或换电池。
目标是跨电压的实际RC有重叠覆盖；不是按电量百分比给数据贴标签。
安排升/降或小块换序与冷却；不要让所有高电压都只对应冷机、所有低电压都只对应热机，而不记录/检查温度影响。
一整轮预先留作独立测试，不参与p、曲线、滤波或模型选择。另一块电池或另一次运行更有价值。
数据少时可做按块交叉验证，但要明确没有独立最终测试集。
0–100%都采过不等于全范围单p通过；只有悬停区有足够跨压覆盖时，正式有效域只能限定到那里。

步骤6：结束、复核和归档
----------------------
记录末尾同步标记；人工disarm并等待力稳定后，PX4再记录一段无推力基准以检查零漂。
复制并保留原始Blackbox与ULog，不只留截图或导出的CSV。保存配置、文件配对、log index、profile、battery_id、异常与暂停记录。
复核首尾标记、缺帧、单位和有效台阶，发现覆盖缺口后针对性补测，不强行拟合。

可选后续检验：
离线留出只证明模型能预测未见数据，不证明运行时补偿闭环已经实测。
有表后可再选有效域内若干目标推力，按不同电压算出的RC手动设置并记录实际力，作为额外补偿验证。必须记录实际达到的RC与目标RC偏差，不能把人工设定误差全部算成模型误差。
项目自动补偿输出的台架/飞行验证另行进行，本次不自动驱动硬件。


## 最小配置修改与恢复记录

以完整有效配置为准，在单独记录中填写：设置名、原值、临时值、所在 profile、修改原因、恢复核对结果。仅把已核实的 debug_mode 从原值临时改为 RX_SIGNAL_LOSS，并启用 DEBUG 字段；PID/FF 隔离及派生增益设置依真实固件逐项记录。未确认空闲的 profile 不覆盖。原 CLI 快照记录 MAVLINK_TELEMETRY，但不能证明当前仍如此。不要重放包含 defaults/save 的 diff 文件。

## 分析交接

先运行 README 中的单文件 inspect；保存 inspection.json 后再填写 analysis_config.yaml 与 sessions.yaml。每个重启/解锁/模式配置边界单独配对；多次时钟重置可用原文件的 sample_slice（零起始、左闭右开行号）明确选择段。首尾匹配边缘至少 6 条用于拟合、2 条用于留出检查，两个集合均需覆盖首尾；每条填写方向和实际信号证据。程序校验锚点附近真实变化，不把两边首帧作为共同零点。最后保留原日志、完整配置、各阶段产物及拒绝原因。
