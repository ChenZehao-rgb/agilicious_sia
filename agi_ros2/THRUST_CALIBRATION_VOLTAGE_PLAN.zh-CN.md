# 单电机推力标定与电压补偿方案

日期：2026-10-28。状态：设计方案；未采集标定数据，未实现新运行时模型，未修改硬件配置或启动电机。

目标：使用电池自然变化的带载电压，标定一张参考电压下的一维推力表和一个电压补偿参数，避免要求精确恒压及二维规则电压网格。MPC 继续输出物理总推力和机体角速度。

## 1. PX4 源码结论

本次固定研究 PX4-Autopilot `main` 提交 `01b35973ec5f36847e889e5f1871580565064c40`，不将主分支实现泛化为所有发布版本、驱动或电池来源。

- [battery.cpp](https://github.com/PX4/PX4-Autopilot/blob/01b35973ec5f36847e889e5f1871580565064c40/src/lib/battery/battery.cpp)：普通 Battery 库先计算每节电压；电流有效且为正时，加上每节内阻乘电流，内阻来自配置或在线估计。随后进行时间常数为 1 s 的一阶滤波。`computeScale()` 使用 `BATx_V_CHARGED / filtered_cell_voltage`，在分母大于浮点 epsilon 时限制到 [1, 1.3]，否则返回 1。系数通过 `battery_status.scale` 发布。
- [AlphaFilter.hpp](https://github.com/PX4/PX4-Autopilot/blob/01b35973ec5f36847e889e5f1871580565064c40/src/lib/mathlib/math/filter/AlphaFilter.hpp)：上述参数 1 的单位为秒，是时间常数；滤波权重为 dt/(tau+dt)。
- [MulticopterRateControl.cpp](https://github.com/PX4/PX4-Autopilot/blob/01b35973ec5f36847e889e5f1871580565064c40/src/modules/mc_rate_control/MulticopterRateControl.cpp)：`MC_BAT_SCALE_EN` 启用后，对有效连接电池发布的正 scale 更新缓存，并在控制分配之前同时缩放归一化推力和力矩设定值，逐分量限制到 [-1, 1]。不是缩放角速度目标，也不是缩放原始 RC 数字。
- [mc_rate_control_params.yaml](https://github.com/PX4/PX4-Autopilot/blob/01b35973ec5f36847e889e5f1871580565064c40/src/modules/mc_rate_control/mc_rate_control_params.yaml)：该功能默认关闭，旨在减轻电池放电造成的性能变化；低电压下最大能力仍然降低。
- [FunctionMotors.hpp](https://github.com/PX4/PX4-Autopilot/blob/01b35973ec5f36847e889e5f1871580565064c40/src/lib/mixer_module/functions/FunctionMotors.hpp)：电机输出层另有推力非线性反解，关系为相对推力 k*x^2+(1-k)*x。电压系数与此反解是不同步骤。

因此，PX4 的上述路径不能简化为“最终 RC 乘满电电压/当前带载电压”，也不能据此断言所有动力系统推力严格按电压一次方变化。

## 2. 本项目采用的候选模型

定义 C 为 FC 接收的 RC 油门值，V 为校验后的带载电压，Vref 为实测覆盖区域中选定的参考电压，Tref(C) 为该参考电压下的全机总推力 N。

候选模型：

```text
T(V,C) = Tref(C) * (V / Vref)^p
s(V) = (Vref / V)^p
Tlookup = Tdesired * s(V)
C = inverse_lookup(Tref, Tlookup)
```

这是借鉴 PX4 的补偿结构后提出的项目模型，不是 PX4 原样算法。p 由实验辨识；p=1、p=2 仅作对照候选。不得把 DShot 数值当成已知电机占空比来证明 p=2。

选择在推力域、查表前补偿，可保留 RC 曲线、min_check 和静态怠速对参考映射的影响。不能直接用 `RC *= s`，也不能把“归一化油门乘 s”和“推力乘 s”混为一谈。原 MPC 指令 `Tdesired` 保持不变，另行记录 `Tlookup`。

本方案使用带载电压，是为了拟合实际端电压下的稳态推力。第一版不移植 PX4 的内阻估计，不对电压加 I*R。否则会把希望建模的负载压降部分消去。测力台与运行时电压位置和标定关系必须一致；必要时单独记录 ESC 端及 FC 检测点电压。

Vref 可在中间电压区域，因而 s 可以小于 1。PX4 的 [1,1.3] 不能直接复制；本项目的补偿上下限由实测支持范围和输出余量确定，超出范围应明确报告不可用，而非静默裁剪后声称推力达到目标。

适用条件：指定 FC/ESC 配置、稳态、近悬停工作区、混控未饱和，以及电压影响可近似用同一个 p 描述。若不同输出区间的 p 明显不同，优先缩小声明范围；需要全范围时再扩展少量分段参数或二维模型，不能用一个系数掩盖系统性误差。

## 3. 单电机测试与飞行 RC 的等效关系

保留实际电机、桨、电调配置和 FC 电机协议。在有防护的专用测力台上用独立测试工具控制单个电机；其余输出停止。测试工具必须具有已验证的失联停机机制和独立断电手段。当前 MSP214 不受 MSP200 的 override 超时机制保护，不能仅依赖主机退出时发送停止。

测得的是 `single_force(V,d)`，其中 d 为实际电机输出。MSP214 的 1000～2000 外部值不是 MSP200 的 RC 值。必须保留两条证据链：

1. 单电机输出 d、电压 V 与力之间的实测关系。
2. 对应实际固件及配置的稳态公共输出 `d=G(C)`，通过源码复用及 FC 输出核验建立；不得从滑块数值直接改名得到 C。

若 G 自身依赖电压或状态（如 VBAT sag compensation、动态怠速、RPM limit），必须显式处理该依赖或限定有效区间。第一版建议由 ROS 输出层统一负责电压补偿，部署前确认 FC 的 `vbat_sag_compensation` 关闭；这是待执行的配置要求，本方案未改动 FC。不得未经核验叠加两层电压补偿。

角速度摇杆居中不保证 PID 输出为零。不得正常解锁后仅接一个电机，将其输出当作理想公共油门。拆桨验证可检查 RC/输出转换，但不能验证带载 RPM、动态怠速和气动推力。

单电机乘 4 是动力一致性及整机安装影响可接受时的近似。优先四套动力依次上同一台测力台；至少对其他电机做悬停区抽查，再做整机总推力抽查。单电机电流不能替代整机电池压降测试。

## 4. 电池供电的数据采集流程

### A. 固定条件与仪器校验

- 保存 FC 版本/构建标识、dump all、diff all、PID/rate profile、ESC 固件和配置、电机/桨型号与方向、测力台几何、环境及电池编号。
- 校准测力零点和已知载荷；每轮前后复查零漂。记录测力轴，保证桨流不吹到称重平台产生额外力。
- 校准 FC 电压与参考电压测量。电压时间戳代表实际采样，不用重复发布的 Health 时间戳替代。
- 检查电流、RPM 和温度读数，缺失时标记未知，不能编造。
- 重新称量起飞质量。当前 YAML mass=0.790 kg，因此初始悬停关注区为单电机约 1.937 N（197.5 gf）；这只是按配置计算的选点依据。

### B. 输出台阶与自然放电

- 不要求停在 16.0 V、15.0 V 等精确电压，也不要求整轮保持恒压。
- 先规划约 12～20 个输出点，覆盖可靠旋转区至计划控制上限；悬停附近加密。初期先测小范围，确认量程和机械条件后扩展。
- 同一组输出点在电池高、中、低电量时重复，每个输出区间应有多个分离的带载电压样本。至少安排 3 个独立扫描块，并另留完整扫描块验证。
- 不只做一次从小到大的连续扫描。交替升扫、降扫、受控打乱的分块扫描；每隔数个点回到悬停附近的锚点，分离电压、温升和时间漂移。所有转移都使用受控斜坡。
- 每台阶初始安排 3～5 s，排除过渡，使用稳定后的 1～2 s 窗口；依据真实力、电压变化延长或拒绝窗口。若需要拉长大量台阶，应安排散热与重新充电，不能把高温漂移归入电压系数。
- 电压缓慢变化可以保留并逐样本处理；明显瞬态、不同步、失步、碰限、力漂移或过大波动单独标记。不能用窗口平均强行掩盖跨越很大的电压变化。
- 使用连续记录的实际带载电压，停机回弹电压和标称电压不能替代。

建议采集能力目标：力 50～100 Hz，独立电压/电流 20～100 Hz（取决于仪器），同时记录 FC 电压作为对照。若仪器较慢，延长稳态平台并仅声明稳态标定；提高轮询频率不等于底层传感器带宽提高。

### C. 原始文件

建议 `raw_samples.csv`：

```text
run_id,battery_id,motor_id,step_id,direction,t_force,t_voltage,
motor_test_value,motor_output_raw,voltage_esc_v,voltage_fc_v,
current_a,force_raw,force_n,rpm,temperature_c
```

明确时间域和 motor_output_raw 单位；不同设备有偏移时保存对齐方法。派生的等效 RC 单列保存，并注明转换工具版本。生成 `steady_windows.csv`，记录窗口范围、均值、标准差、漂移、样本数、有效性及拒绝原因。gf 转 N 使用 0.00980665。

## 5. 一维表及补偿参数提取

1. 保留原始数据只读；校准、时间对齐、分段、去过渡、检查零漂。
2. 根据稳态 d=G(C) 建立等效 RC。动态怠速活动区、混控饱和区或无法唯一转换的点单独处理。
3. 选实测覆盖充分的 Vref。对重复相同输出点的数据比较 log(F) 与 log(V/Vref) 的变化，辨识共同 p。低于测量可信下限的力不参加对数拟合，也不人为增加 epsilon 制造正值。
4. 联合拟合单调参考曲线与 p，或先用重复输出点估计 p 再构造参考曲线：`Fref_i = Fmeasured_i * (Vref/Vi)^p`。离线初始稳态拟合使用对齐的带载电压，随后用候选运行时电压滤波器重放整段数据，检验延迟影响。
5. 比较 p=0（无补偿）、p=1、p=2、实测 p 的独立验证误差；不要预设必须接近 2。按完整扫描块或电池划分验证集，不随机拆分相邻采样点冒充独立验证。
6. 检查电压—输出覆盖与 p 的置信区间；单次扫描输出和电压强相关时，不认定 p 已辨识。检查归一化残差对电压、输出、温度、扫描方向是否仍有趋势。
7. 四套分别测量时优先求和构造总推力曲线；若采用同一 p，需验证各电机均适用。仅测一套时乘 4 并明确系统性不确定性，不把复制四次视为误差平均。
8. 参考曲线使用单调分段线性插值；不补未测的零推力端点，不强行抹平怠速平台、迟滞或饱和。

输出 `reference_thrust.csv` 的新格式建议为两列：`rc_throttle,total_thrust_n_at_vref`。元数据文件保存 schema_version、input_domain=fc_rc、force_scope=vehicle_total、Vref、p、有效电压/输出/推力范围、补偿界限、电压滤波定义、FC/ESC 配置哈希、单电机倍乘方式、训练/验证分组、误差及原始数据哈希。

该两列格式和参考补偿模型尚未被当前加载器支持；不能直接填入现有 flight.thrust_table，也不能伪造两个相同电压行绕过检查。

## 6. 验证与接受条件

以下数值是建议的首轮实验目标，不是飞行安全标准或已经通过的结果：在预先指定的悬停及纠偏区，独立稳态点平均推力相对误差不超过 5%、最坏点不超过 10%；报告测量不确定度及重复性，并检查无明显随电压单向增加的残差。低推力区使用绝对误差，不能只看相对误差。

- 对未参与拟合的电池/扫描块，在自然下降的电压下请求相同目标力，比较实际测力：无补偿、候选补偿分别验证。
- 单电机验证目标为 Tdesired/4（四套一致近似），补偿计算与运行时相同。单电机台结果不能证明整机带载电压和推力准确。
- 验证低电压最大输出以及升降台阶；记录采样、滤波、推力恢复延迟和补偿引发的额外电压下降。防止低压时不断加输出、加大压降后继续补偿。
- 比较真实 FC 电压链路和高频仪器重放结果，再选择滤波时间常数及回读频率。避免仅在高频理想电压上验证算法。
- 在适当整机夹具上做多个推力点抽查，检查四倍假设及线束压降。后续再分阶段检查真实飞行中的角速度跟踪和悬停。
- 若误差超标，先核对输出域、RC 转换、时间对齐、温升和电压测量；再决定缩小范围或扩展模型。不能只增大 p 使某一个悬停点对上。

## 7. 项目接入设计及限制

当前运行时仅支持 table/quadratic；hardware.yaml 当前为 quadratic。现有 table 要求至少两个电压点，按电压插值，不支持本方案的一维表。需新增一个明确命名的参考表补偿模型及独立加载器，更新 launch/config 校验、输出状态来源与离线测试。模型名称和参数在实现前仍属于设计，不是已支持的配置。

运行链路：

```text
MPC: Tdesired [N], body_rates [rad/s]
    -> valid fresh loaded voltage -> filtered voltage -> s(V)
    -> Tlookup = Tdesired*s
    -> 1D reference table inverse -> RC throttle -> MSP200
```

补偿不改变 MPC 的物理总推力语义，不缩放 body_rates。PX4 还补偿内环力矩，而本项目内环在 Betaflight 内部，不能通过把角速度目标乘 s 来模拟这一步；低电压角速度跟踪需独立验证。

记录至少：原始电压及其采样年龄、滤波电压、Vref、p、s、Tdesired、Tlookup、输出 RC、有效范围、饱和/拒绝原因及模型版本。补偿范围、目标力或 RC 超出标定范围时继续使用明确的故障处理，不能静默裁剪并声称已实现请求推力。

当前配置 `msp.battery.rate_hz=2.0`、`battery_timeout=1.5`，Health 只有 battery_voltage，没有专用电压采样时间或电流字段。现有新鲜度由证据节点判定并将过期值编码为 NaN。2 Hz 可研究慢速放电补偿，但不足以宣称快速负载压降补偿。需要记录真实电池事件时间，评估较高有效回读频率（如 10～20 Hz）对串口及控制时序的影响；不能用更高频 Health 心跳刷新旧测量。

在允许电压区间内，候选模型可提供的上界近似为 `Tmax(V)=Tref(Cmax)*(V/Vref)^p`，还应预留混控姿态余量。当前 MPC 如继续使用固定推力上限，应按允许范围内最弱能力设置，不把参考电压最大推力当作低压能力。下限同样需覆盖连续可靠旋转区；停机命令保持独立语义。

软件验证应覆盖 V=Vref、较高/较低电压、p=0、单调性、单位、逆查表、整数 RC 量化、无效/陈旧电压、超范围推力、补偿限界、重启滤波初始化及影子模式不输出。用真实查表函数离线验证；当前 shadow 输出提前返回，不能以 shadow 正常运行代替逐指令映射验证。

实施顺序：先完成测力台及采集安全闭环，再采集重复电压覆盖数据，离线辨识和独立验证，随后实现参考表模型与遥测，最后做整机抽查和分阶段物理验证。单独完成文档或软件测试不代表已经完成实机标定。
