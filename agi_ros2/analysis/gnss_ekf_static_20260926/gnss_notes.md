全程坐标范围含潜在真实运动，不应称为静止漂移或绝对位置误差。用户确认的前 100 s 内，原始 GNSS 已有显著慢漂移：用 `[0,10)` 与 `[90,100)` 均值避免单帧端点影响，ENU 位移为 `[-0.846, +3.992, -8.559] m`，水平 4.080 m。高度为原始 MSL 高减固定原点，不是气压计高度。

供 EKF 使用相同分析时间窗口比较：本地导航接收时间 `[6,100) s` 有 912 帧，E/N/U 范围为 `1.131 / 4.298 / 9.290 m`；相对窗口首帧的最大水平偏移为 `4.389 m`，首尾 ENU 位移 `[-0.890, +4.298, -9.290] m`。前 10 s `[6,16)` 与末 10 s `[90,100)` 均值位移为 `[-0.561, +3.940, -7.933] m`，水平 `3.980 m`。这些计算使用本地消息的实际坐标和接收时间，原始导航精度/速度按整数测量时间戳一对一关联；详细结果保留于 JSON 的 `common_6_100s_*` 字段。

前 100 s 的速度积分 ENU 位移为 `[+0.760, +0.914, -1.934] m`，同一源时间区间位置差为 `[-1.106, +4.076, -9.350] m`；位置差减速度积分为 `[-1.866, +3.162, -7.416] m`。积分采用源 header 时间与梯形法，只保留相邻间隔为正且不超过 0.3 s、同一源会话的段；本包没有被排除的区间。这说明慢变位置解与速度测量不完全一致；不能把位置漂移全解释成真实运动，也不能要求滤波器用小幅速度噪声完全消除位置偏移。有限差分位置速度受位置量化/时间抖动影响，不将单帧差分作为真值。

原始经纬高按记录原点重新转换，与全部 2396 帧有效 `LocalNavigation` 的坐标逐一按整数时间戳匹配：最大 E/N/U 误差约 `5.4e-9 / 2.4e-9 / 8.0e-15 m`。因此这批慢漂移已存在于原始导航解；没有证据支持由 Python 坐标转换引入米级漂移。前 100 s heading 仅在 27.2°–27.5°，首尾差 +0.1°，并无明显航向跳变解释这段位置漂移。

全程均 `fix_type=3`、heading_valid 与 clock_aligned 为 true，源会话不变，无重复或乱序源时间戳，没有大于 0.3 s 的导航间隙。MAVLink 诊断的 bad_frames、wrong_source、duplicates、stale、rejected_sync、tx_errors 全部为零。TIMESYNC RTT 中位 1.94 ms、最大 3.25 ms。这些支持传输/时间链路在记录中正常，但不等于 GNSS 测量真实无延迟或定位误差小。

录包开头存在测量时间早于 metadata 起点的帧：主窗口包含它们，接收时间延迟最大 0.408 s。改用源时间 `[0,100)` 的敏感性检查有 966 帧，首尾水平 4.277 m、垂直 -9.440 m，水平直径 4.525 m、垂直范围 9.810 m，结论不变。该口径最大接收年龄为 0.105 s。缓存具体位置仅凭 CSV 无法确定。

全程 190.831 s 一帧 heading 跳变 -105.9°，另有约 175–192 s 的大幅变化。该段不属于用户确认的静止窗口，可能与旋转/姿态估计/磁环境有关，需与 IMU 及实物动作记录核对；本子分析不将其直接判为磁罗盘异常。

全部本地观测 `accuracy_known=true`，但 `accuracy_ok=false`，说明有数值精度报告与满足飞行门槛是两回事。原始 accuracy 只是接收机自报估计；没有测量真值/卫星数/DOP/CN0/天线环境数据，不能凭该包确认多径、遮挡、卫星几何或接收机内部滤波哪一项是漂移根因，也不能把自报 accuracy 当作漂移上限。
