# CM5 静止 EKF 初始化验证（2026-09-26）

在连接飞控的 CM5 上，仅将 `hardware.yaml` 的
`fusion.imu_gravity_tolerance` 从 `0.5` 调整为 `0.7 m/s²`，
使用 `diagnostic_only:=true` 实测得到 `initialized=true`、`imu_ready=true`、
`navigation_valid=true`，融合位置、速度及导航观测时间戳正常更新。

## IMU 参数依据

修改前诊断包中的 57,470 个 IMU 样本覆盖约 115.31 秒。
按初始化器相同规则计算的 54,473 个完整 3 秒窗口中：

- 平均加速度模长为 `9.18538–9.26999 m/s²`。
- 相对项目重力常量 `9.8066 m/s²` 的偏差为 `0.53661–0.62122 m/s²`。
- 容差 `0.5` 时全部失败；`0.65` 已覆盖全部窗口，采用 `0.7` 留出少量余量。
- 样本数、陀螺偏置、陀螺噪声和加速度噪声均通过原有检查，无需调整其他门限。

调整初始化门限不会缩放或校准 IMU 输入。EKF 继续使用原始加速度，
由 GNSS 更新参与估计状态与偏置。不能把门限通过解释为加速度计已完成标定。

## 导航参数与实际融合

当前 `gnss_adapter.py` 已逐帧使用接收机报告精度构造观测方差：
`max(报告精度, 标准差下限)²`。保留现有水平 `1.0 m`、垂直 `2.0 m`、
速度 `0.3 m/s` 的下限，以及航向 `10°` 的标准差。

修改前包中接收机报告精度如下，完整统计见 `parameter_window_stats.json`：

| 报告精度 | P95 | 最大值 |
|---|---:|---:|
| 水平 | 0.917 m | 0.936 m |
| 垂直 | 1.551 m | 1.566 m |
| 速度 | 0.339 m/s | 0.562 m/s |

水平 `1.0 m`、垂直 `2.0 m`、速度 `0.6 m/s` 可以作为覆盖该包报告值的
临时诊断接纳门限，但缺少外部真值，不能由此证明真实定位误差。
本次未将这些候选值写入硬件的飞行准入门限。
修改后的新包中，水平报告精度最大已达到 `1.018 m`，说明前一段数据的接纳范围
不能保证覆盖后续环境变化。新包水平、垂直、速度报告精度 P95 分别为
`0.997 m`、`1.790 m`、`0.336 m/s`。

`navigation.max_*_accuracy` 和 `fusion.max_*_stddev` 仍为 `0`，因此
`navigation_ready`、`estimator_ready` 仍为 false。这不阻止实际 EKF 初始化和
GNSS 更新。此时 `navigation_accepted_updates` 也会被准入逻辑清零；应结合
`navigation_valid`、持续推进的 `rtk_stamp/covariance_stamp`、有限创新和状态来验证融合。

## 验证与复现

- 修改后整段录包验证见 `validation_summary.json`，包含初始化连续性、
  导航时间戳推进、重置/拒绝计数、协方差及末段传感器检查。
- 录包长 `95.47 s`，第 `10.92 s` 初始化；随后 `84.55 s` 的 `42,226` 条
  融合消息连续有效，重置计数固定为 `2`。
- 导航与协方差时间戳各推进 `825` 次，导航拒绝计数一直为 `0`，
  有限创新平方最大 `18.91`，低于门限 `24.322`。
- 初始化后前 `51` 帧尚无首次导航创新，统计文件用 `null` 表示非有限值。
- 末段 `8,489` 个完整 IMU 窗口在容差 `0.7` 下全部通过。
- `python3 agi_ros2/test/test_runtime_config.py`：16 项通过。
- `git diff --check`：通过。
- 本次仅使用诊断模式，测试进程已正常退出。

本次验证的是初始化与持续融合，并未验证绝对定位精度。初始化 10 秒以后的
融合高度范围仍为 `-6.892–0.800 m`；没有外部真值，不能由较小的后验协方差
反推出同等的真实精度，也不据此缩小导航噪声参数。

源录包路径记录在两个统计文件中。仍使用原命令运行：

```bash
./agi_ros2/scripts/launch.sh mode:=hardware diagnostic_only:=true
```

配置由启动脚本直接读取，本次 YAML 修改无需重新编译。
